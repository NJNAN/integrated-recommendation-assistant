# 代码阅读指南（30 分钟读懂这个仓库）

> 这个仓库不是“一个项目”，而是**三个项目的代码放在一起**：模块三（本仓库主体）、
> 模块一的冻结发布包（`vendor/01_recommender_system/`）、模块二的源码（`vendor/02_multimodal_ai_assistant/`）。
> 先记住一句话：**模块三通过 HTTP 调模块一、通过子进程调模块二，两边都不 import 对方内部代码。**

> 👥 按人分工的阅读清单（谁精读哪些文件、每人的自测问题）：[阅读清单](阅读清单.md)

## 4. 三个项目的边界（为什么这样组织）

| 关系 | 方式 | 代码位置 |
| --- | --- | --- |
| 模块三 → 模块一 | 公开 HTTP：`/api/auth/login`、`/api/recommendations`（分页） | `assistant/adapters.py`；服务代码在 `vendor/01…/release/web_system/` |
| 模块三 → 模块二 | JSON-lines 子进程：启动模块二自己的 Python，标准输入输出传 JSON | `assistant/module_two.py` + `integrations/module_two_worker.py`；被调代码在 `vendor/02…/src/` |
| 模块三内部 | 直接函数调用 + 四个数据结构 | `assistant/` |

三条原则：
1. 模块三**不 import** 上游内部模块，所以上游可以独立替换、独立降级。
2. `vendor/` 只是**给人读的副本**，本仓库的 `import` 不会走到它（只有子进程会以它为工作目录启动）。
3. 上游不可用时，模块三必须还能跑：模块一挂 → 离线目录；模块二挂 → 手动输入。

## 5. 只想跑起来

```powershell
# 最省事：纯离线，只要 Python 标准库
$env:IRA_PROFILE = 'demo'; python -B app.py          # http://127.0.0.1:8080

# 接真实商品目录（需要当前解释器装 Flask；用仓库里的 vendor 模块一）
python -m pip install flask
python -B app.py

# 证据与测试
python -B scripts/run_all.py
python -B -m unittest discover -s tests -v
```

## 6. 常见困惑

| 困惑 | 答案 |
| --- | --- |
| 为什么 `vendor/` 里的代码不参与运行？ | 模块三只通过 HTTP/子进程调它；把它放进来是为了让人能读、能对照，不改变架构边界 |
| 为什么模块二没有 `.venv`？ | venv 有几 GB 模型和依赖，不适合进仓库；没有它时媒体接口返回 503，页面保留手动输入 |
| 模块一没有 173 MB 的模型 pickle，为什么还能跑？ | 冻结服务的打分结果已经在 `release/expected/submission_v2_R1_head48.csv`，服务只读这个结果 + 商品目录，不需要原始模型 |
| `data/module_one_catalog.json` 和 `vendor/01…/catalog.csv` 有什么区别？ | 后者是上游原始商品表；前者是模块三把商品表 + 历史交易合成后、带来源证据的目录 |
| 想改模块一的代码怎么办？ | 去原项目改，再重新复制到 `vendor/`；不要让模块三依赖 vendor 里的改动 |
