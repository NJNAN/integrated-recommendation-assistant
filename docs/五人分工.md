# 五人分工与答辩讲解

> 代码按**五个人的模块**组织：每人一个阶段、一组文件、一组可重跑证据，代码行数尽量均匀（每人 500–600 行）。
> 答辩时每人 1–2 分钟讲自己的模块，再一起讲跨模块协议；不用背整份代码。

## 2. 每人的讲解要点（各 1–2 分钟）

> 每人要精读哪些文件、读到什么程度、读完的自测问题：见 [阅读清单](阅读清单.md)。

### 成员1 · 契约与接入（阶段1）
1. 打开 `assistant/contracts.py`：`InteractionEvent`（统一输入）、`RecommendationRequest`（推荐请求）、
   `RecommendationItem`（结果）、`EvidencePack`（证据）。四个结构就是四份“合同”，跨模块只传它们。
2. 指着 `_metadata`：`trace_id/user_id/session_id/timestamp/source` 必填，时间必须带时区；
   非法输入抛 `ContractError` 并带错误码（`INVALID_EVENT` 等），不会静默返回空字典。
3. 打开 `assistant/adapters.py`：模块一走公开 HTTP（登录 + 分页，独立 CookieJar），
   模块二走 JSON-lines 子进程；两边都不读对方内部变量。
4. 打开 `app.py`：默认 auto 接入模块一，失败就在 stderr 打警告并回退 `offline_demo_settings()`，
   保证离线也能演示。证据：`python -B scripts/01_contract_test.py` → 6/6。

### 成员2 · 输入与意图（阶段2）
1. `understanding.py::understand`：从文本/转写/视觉标签/手势抽出六类意图与五个槽位；
   视觉标签低于 0.7 只记进 `ignored_labels` 不猜；同一轮出现两个颜色就是 `conflicts`。
2. `session.py`：`merge` 合并多轮条件、`undo` 撤销、`end` 清理；正负偏好存在 `preferences`，
   会话按 `(user_id, session_id)` 隔离并有 1800 秒 TTL。
3. `media.py`：媒体入口只做三件事——解码校验、交给模块二识别、转成统一事件；
   `module_two.py` 负责子进程生命周期与超时回收。
4. 证据：`python -B scripts/02_context_test.py` → 30/30；打开 `outputs/stage02_error_cases.md`
   讲“预算三百元→追问、颜色冲突→拒绝更新、撤销→恢复上一步”。

### 成员3 · 召回与编排（阶段3）

> 🧩 **模块一对接代码讲稿（模块一里和阶段3 直接相关的代码）：**[成员3_模块一对接代码讲稿.md](成员3_模块一对接代码讲稿.md)

> 📜 **逐函数讲稿（按文件→函数→参数→怎么做，可直接照着念）：**[成员3_讲稿_按文件逐函数.md](成员3_讲稿_按文件逐函数.md)

> 📖 **详细讲解稿（含真实数值走查、逐段代码、三档逐字稿、25 个追问、现场小实验）：**
> [成员3_召回与编排_讲解.md](成员3_召回与编排_讲解.md)

1. `recommendation.py`：先**硬约束过滤**（品类/颜色/预算/缺失价格）再打分，所以高分不能突破预算；
   召回有 popularity / category / context_tags / similarity / module_one_http 多路来源，`sources` 可追溯。
2. 打分公式（要能背）：`0.4*热门 + 0.2*场景命中 + 相似度 + 0.3*上游分数 + 2.5*反馈 + 0.06*标签亲和`，
   排序 `(-score, item_id)`，同输入必得同结果。
3. `orchestrator.py`：事件→意图→会话→请求→推荐→解释，每步写 `trace`；出错回滚会话快照。
4. `module_one.py`：把模块一的 CSV 合成商品目录（保留 GBP 历史单价与来源 sha256），
   并负责启动/关闭模块一的冻结服务。
5. 证据：`python -B scripts/03_orchestrator_demo.py` → 4/4（正常/空集/超时降级/确定性复现）。

### 成员4 · 解释与呈现（阶段4）
1. `explanation.py`：只读 `item.evidence` 的事实；引用片段必须属于本商品（`catalog:<id>:` 前缀），
   属性不一致就返回 `EVIDENCE_MISMATCH`、没证据返回 `INSUFFICIENT_EVIDENCE`，**不编造**；
   `speech_text == text` 方便接 TTS。
2. 打开网页：四种输入方式、商品卡片、点赞/倒踩/找相似、比较、撤销、新会话、证据折叠、trace 导出。
   `app.js` 只做“调 `/api/events` + 渲染”，没有业务逻辑，也没有内联样式（服务端有 CSP）。
3. 证据：`python -B scripts/04_explanation_test.py` → 5/5；
   打开 `outputs/stage04_abnormal_explanations.md` 讲三种降级。

### 成员5 · 反馈与服务（阶段5+6）
1. `feedback.py::apply_feedback`：只允许反馈当前会话最近展示过的商品，**覆盖不累加**，
   非法目标抛 `INVALID_FEEDBACK` 并回滚会话。
2. `server.py`：只监听 127.0.0.1；`/api/events`、`/api/media/*`、`/api/health`；
   Origin/Content-Type/大小校验 + CSP + 不记录请求体；错误映射 400/413/415/503/504/500。
3. `scripts/05`：固定用户、查询、候选池、TopK，只让反馈变化，对比正/负/重复/非法/跨会话五种情况。
4. `scripts/06`：voice/vision/gesture 三条链路 + 故障降级 + 非法输入 + 会话结束 + 空集，全部断言同一 `trace_id`。
5. `run_all.py` 汇总六阶段；`test_report.py` 跑回归测试并落盘。

## 3. 跨模块协议（每人都要能说，30 秒）

- 数据流：`InteractionEvent` →（意图/会话）→ `RecommendationRequest` →（召回/打分）→
  `RecommendationItem` + `EvidencePack` →（解释）→ 响应 `items`。
- `trace_id` 贯穿全部环节：响应的每个 `trace[].trace_id` 与每件商品的 `trace_id` 都相同。
- 状态只有六种：`ok / empty / needs_clarification / conflict / ended / error`；
  任何失败都带 `error.code`，前端按 `status` 显示不同提示。
- 降级：模块一不可用→离线目录；模块二不可用→手动输入；解释缺证据→降级不编造；
  硬约束空集→不放宽，提示调整。

## 4. 代码规模（为什么说“简化”）

> 口径：**总行** = 含空行与注释的全部行；**代码行** = 去掉空行、`#` 注释、docstring 之后的实际代码行。
> 判定“简化了多少”看**代码行**最公平（注释是为了答辩好看，不算逻辑）。

| 部分 | 简化前（总行 / 代码行） | 现在（总行 / 代码行） | 变化 |
| --- | --- | --- | --- |
| 核心业务 `assistant/`（不含旧 `evaluation.py`） | 1,394 / 1,234 | 1,906 / 1,201 | 代码行 -3%：功能一个没减，主要删掉防御式冗余；总行变多是成员3 给每个函数补齐了参数说明（每个参数是什么/从哪来/取值），代码行一点没变 |
| 证据与验收（`scripts/` + 旧 `evaluation.py`） | 575 / 507 | 881 / 622 | 总行 +39%（拆成 6 个独立脚本 + 共用 `_stage.py`），代码行 +23%，换来“谁写谁讲、可单独重跑” |
| 回归测试 `tests/` | 998 / 831 | 579 / 370 | **代码行 -55%**：11 个文件 → 5 个，只测本人模块 |
| 前端 `web/`（app.js + html/css） | 203 / 196 | 472 / 457 | 旧版一行塞 4–5 句（平均 130 字符/行），新版一行一句（43 字符/行）；字节 21.7KB → 23.9KB |
| 额外脚本（07/08 模块验收、打包、提交检查） | 510 / 434 | 0 | 任务书没要求，删除，改用 README 手工清单 |
| 模块一/二进程入口 `integrations/` | 146 / 128 | 146 / 128 | 不变（模型细节不在本项目） |
| 配置与入口（`settings.py` + `app.py`） | 134 / 105 | 109 / 88 | -16% |
| **项目合计** | **3,961 / 3,440** | **4,093 / 2,866** | **代码行 -17%**；最大业务文件（按代码行）506 → 223 行；每人 500–600 代码行 |

比行数更重要的是结构：业务代码集中在 12 个文件、每个文件只做一件事，最大业务文件（按代码行）从 506 行降到 223 行；
验收逻辑从“一个 506 行的大文件”变成“每人一个 50–150 行脚本”；测试从 11 个文件收敛到 5 个；
任务书没要求的 510 行脚本直接删除。前端行数增加是**排版变化**（旧版一行多条语句），字节数基本持平。
